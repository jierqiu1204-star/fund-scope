## Requirements
### Requirement: ETF Label Validation Dashboard
The system SHALL provide an ETF label validation view that summarizes historical outcomes for buy-observation labels and entry-timing labels.

#### Scenario: User views label validation
- **WHEN** validation results exist for ETF labels
- **THEN** the UI shows label name, entry-timing label, sample count, forward return summary, drawdown summary, win rate, data date, and confidence state

#### Scenario: Validation results are missing
- **WHEN** no completed validation run exists
- **THEN** the UI shows a Chinese waiting state and MUST NOT present labels as historically validated

### Requirement: Label Validation Confidence Is Visible
The system SHALL mark every label validation summary as sufficient, limited, insufficient, or stale.

#### Scenario: Label evidence is sufficient
- **WHEN** a label combination has enough completed samples and fresh validation data
- **THEN** the dashboard displays it as sufficient evidence with the sample count

#### Scenario: Label evidence is insufficient
- **WHEN** a label combination has too few samples or stale validation data
- **THEN** the dashboard displays `样本不足` or `验证过期` and MUST NOT describe the label as reliable

### Requirement: Label Validation Is Research Only
The system SHALL keep label validation output separate from live labels and MUST NOT automatically rewrite live scores or labels based only on validation results.

#### Scenario: Historical evidence is weak
- **WHEN** a label combination has weak historical forward outcomes
- **THEN** the UI displays the weakness as evidence while preserving the live ranking label generated by the current scoring rules
