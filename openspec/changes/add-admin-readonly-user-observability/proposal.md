## Why

当前系统已经支持用户邮箱注册、审批和追踪持仓按用户隔离，但管理员只能做审批，缺少一个只读视角来查看用户账号使用情况、追踪了哪些资产、是否有提醒链路异常。qje 作为管理员需要能排查用户问题，但不能代用户修改持仓、追踪、买入价或提醒状态。

## What Changes

- 明确数据边界：
  - ETF / 基金行情、短线排序、AI/规则研究说明、观察组合是全局共享数据，所有已批准用户看到的是同一套市场数据。
  - 用户私有数据包括：追踪持仓、买入价/份额、提醒记录、收件邮箱、通知设置、登录账号状态。
- 新增管理员只读用户观察能力：
  - qje / super admin 可以在用户列表里查看用户账号概况。
  - 管理员可以进入某个用户的只读详情页，查看该用户追踪了哪些 ETF/基金、买入日期、买入价、估算盈亏、当前持仓处理状态、最近提醒和邮件发送状态。
  - 管理员可以查看该用户的 SMTP/邮件配置状态摘要，但不能查看 SMTP 授权码明文。
- 明确禁止管理员代改业务数据：
  - 管理员只读页面不能修改别人的追踪持仓、买入价、份额、备注、提醒状态、收件邮箱或通知设置。
  - 管理员仍可保留现有“批准/禁用用户”的账号管理权限。
- 新增审计边界：
  - 管理员查看用户详情应记录只读访问日志或至少在后端日志中可追踪。
  - 普通用户不能访问管理员只读接口。
- 不改变现有市场数据、短线排序、邮件提醒、追踪计算逻辑。

## Capabilities

### New Capabilities
- `admin-user-observability`: 管理员只读查看用户账号、追踪持仓、提醒状态和邮件配置摘要。

### Modified Capabilities
- `email-auth-approval`: 用户列表从“审批列表”扩展为“账号管理 + 只读详情入口”，但账号审批权限保持不变。
- `tracked-position-exit-strategy`: 明确普通用户只能访问自己的追踪，管理员只读接口可以读取别人的追踪快照但不能修改。
- `short-term-research`: 明确市场 ETF/基金研究数据是全局共享，不按用户隔离。

## Impact

- 后端：
  - 新增 super-admin-only 只读 API。
  - 查询用户追踪持仓和提醒记录时支持 admin target user id，但写接口继续只允许 owner 修改。
  - 隐藏敏感字段，例如密码 hash、SMTP 授权码、JWT、服务器密钥。
- 前端：
  - 用户管理页增加“查看详情”入口。
  - 新增管理员用户详情页或抽屉，显示只读账号概况、追踪持仓、最近提醒、邮件状态。
  - 页面明确标注“只读模式”。
- 安全：
  - 所有管理员只读接口必须验证 `is_super_admin=true`。
  - 非管理员访问返回 forbidden。
  - 管理员只读页面不能复用普通用户 PATCH/close 等写操作。
- 测试：
  - 覆盖管理员能读、普通用户不能读、管理员不能通过只读接口修改、敏感字段不泄露。
