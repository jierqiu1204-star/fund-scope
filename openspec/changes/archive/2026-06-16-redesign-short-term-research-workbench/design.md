## Context

`/short-term` 是当前项目的主入口，已经包含 ETF/场外基金模式、短线排序、图表、买入追踪、邮件提醒状态和数据任务。现状功能完整但信息密度和视觉层级不清，用户容易把“榜单观察状态”和“已买入后的持仓处理状态”混在一起。

## Goals / Non-Goals

**Goals:**
- 把 `/short-term` 改成面向短线研究的工作台：左侧快速浏览，右侧聚焦单只资产判断。
- 让新手能在首屏理解数据日期、榜单状态、资产详情和自己已买入持仓的处理状态。
- 保留现有 API、排序规则、提醒规则和图表数据，优先通过前端重排和组件拆分提升可用性。

**Non-Goals:**
- 不新增交易、自动下单、券商连接或支付宝连接。
- 不改变后端评分、标签、邮件触发规则或数据同步任务。
- 不引入新的 UI 框架或图表库。

## Decisions

- 采用“顶部状态栏 + 左侧榜单 + 右侧详情”的工作台布局，而不是继续纵向堆叠所有模块。这样能让用户在同一屏内完成选择、看图和判断。
- 榜单卡片改为紧凑摘要，只展示排名、名称、分数、观察标签、关键指标和一句原因；详细解释、图表和风险放到右侧详情。
- 买入追踪从资产详情中的附属内容提升为“我的持仓观察”区域，明确展示当前盈亏、持仓处理状态、最近提醒和邮件状态。
- 继续使用现有 Tailwind、Recharts、React Query 和项目 UI 组件；必要时拆分 `short-term/page.tsx` 内部组件，降低单文件复杂度。
- 文案统一区分两类状态：榜单是“买入观察状态”，追踪持仓是“持仓处理状态”。

## Risks / Trade-offs

- 工作台布局在移动端空间有限 → 移动端采用单列顺序：状态、榜单、详情、持仓观察，并提供锚点或切换按钮减少滚动成本。
- 信息压缩可能隐藏重要风险 → 榜单保留最高优先级风险提示，详情中完整展示风险解释和反方观点。
- 拆分组件可能影响已有交互状态 → 保持查询参数、选中资产、分页和追踪表单状态兼容，先做纯前端重排。
