## Context

`/short-term` 是 FundScope 的主工作台。当前左侧榜单已有方向筛选、搜索、范围筛选、排序和分页，但用户更关心“哪些 ETF 现在处于可观察/谨慎/回避状态”。单纯把“实时综合排序”放在明显位置，容易让新手把分数理解成“最该买”，而不是先看标签组合。

前端已经拿到买入观察状态、盘中/日线买点状态、持仓追踪状态、提醒状态等字段。第一版可以在页面内完成标签筛选，不需要改评分算法和邮件链路。

## Goals / Non-Goals

**Goals:**

- 在 `/short-term` 榜单区域增加标签多选筛选。
- 明确区分“筛选”和“排序”：
  - 筛选决定看哪些 ETF。
  - 排序决定筛选结果怎么排列。
- 用 Geist 风格做紧凑、可扫描、低装饰的筛选控件。
- 保持移动端可用，不增加横向溢出。

**Non-Goals:**

- 不改变 ETF 评分、标签生成、动态阈值、策略回测和邮件提醒。
- 不新增后端数据库字段。
- 不删除排序能力。
- 不把任何标签写成“可以买”或“推荐买入”。

## Decisions

### Decision 1: 第一版前端筛选，后端 API 保持不变

页面已有 `conclusion`、`entry_timing_label`、`live_entry_timing_label`、追踪状态和提醒状态。第一版直接基于已加载的当前页数据筛选，避免改后端分页、缓存和排序接口。

替代方案是新增后端 `label_filters` 查询参数。这能让分页总数更精确，但涉及 API、缓存和查询逻辑，应该等前端交互验证后再做。

### Decision 2: 标签筛选放在排序之前

控件顺序调整为：

```text
方向/搜索
标签筛选 chips
排序和范围
分页
榜单
```

排序文案从“实时综合排序”降级到排序菜单里。列表默认仍按当前默认排序返回，但用户视觉上先看到“筛选状态”。

### Decision 3: 使用 popover + checkbox + chips

Geist 风格要求高密度、低装饰、细边框、紧凑按钮。设计为：

- 一个 `标签筛选` 按钮，显示 `已选 N`。
- 打开后显示三组 checkbox：
  - 买入观察。
  - 今日/盘中买点。
  - 持仓状态。
- 按钮下方显示已选 chips，可单个删除。
- 快捷按钮：`稳妥观察`、`高位谨慎`、`只看持仓`、`清空`。

不使用大色块卡片，不引入新依赖。

### Decision 4: 默认筛选应保守

默认建议选择 `短线观察` + `健康回踩/趋势延续`，但为了避免用户以为系统隐藏其他资产，第一版可以有两种安全口径：

- 默认不过滤，只显示快捷按钮 `稳妥观察`。
- 或默认启用稳妥观察，并在顶部显示“已筛选，可清空”。

推荐第一版默认不过滤，保留用户现有浏览习惯；新增快捷按钮让用户一键切换到稳妥观察。

## Risks / Trade-offs

- [Risk] 前端当前页筛选会让当前页显示数量变少。  
  Mitigation: 切换标签筛选时重置到第一页；空状态提示“当前页无匹配，可清空筛选或换页”。如体验仍差，再扩后端筛选。

- [Risk] 标签太多导致控件复杂。  
  Mitigation: 分三组展示，并提供快捷组合；默认只显示已选 chips。

- [Risk] 用户把“健康回踩”理解成买入指令。  
  Mitigation: 筛选区文案写“筛选观察状态”，详情仍说明“需人工判断，不是交易指令”。

- [Risk] 移动端 popover 操作困难。  
  Mitigation: 移动端使用全宽折叠面板或 bottom-sheet 风格区域，不做悬浮大弹窗。
