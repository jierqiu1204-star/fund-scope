## Context

FundScope 当前已经有两条相关链路：一条是短线研究的确定性排序和 LLM 研究说明，另一条是用户已买入持仓的离场提醒。确定性排序、动态止损线、移动止盈线由公开价格和规则计算；LLM 通过 OpenAI 兼容接口生成解释，并有 JSON schema 校验和规则兜底。

当前问题集中在三个点：AI 提示词和兜底文案有乱码，影响输出质量；`take_profit_watch` 只做网页提示，盈利较多时不会邮件提醒；部分持仓提醒依赖最新短线榜单上下文，导致已追踪资产不在榜单中时提醒不够稳定。

## Goals / Non-Goals

**Goals:**
- 修复 AI 研究说明相关中文文案，保证模型输入、兜底输出和页面展示为正常中文。
- 让盈利达到动态止盈观察线的持仓可以发送“止盈观察提醒”邮件。
- 保持动态线由透明规则计算，AI 只解释规则结果和风险。
- 让已追踪持仓的硬止损、移动止盈、趋势转弱、止盈观察不依赖是否进入最新短线榜单。

**Non-Goals:**
- 不训练模型，不让 AI 直接决定买入、卖出、止盈线或止损线。
- 不连接券商、不连接支付宝、不自动下单。
- 不把暂无 IOPV、行情滞后、数据结构不完整升级成邮件卖出提醒。

## Decisions

1. **AI 作为解释层，不作为风控决策层。** 动态线继续由近 20 日波动、ATR 类波动、最低保护值、最高盈利和回吐幅度计算。这样结果可解释、可测试，也避免模型输出不稳定影响真实持仓提醒。

2. **止盈观察邮件使用较弱但明确的提醒语气。** `take_profit_watch` 可以发邮件，但邮件标题和正文必须写成“止盈观察提醒”，说明它不是卖出指令，只提醒用户在证券账户或支付宝人工复核。

3. **持仓分析先独立产出，再合并榜单上下文。** 硬止损、移动止盈、趋势转弱、止盈观察应只依赖持仓、价格、动态线和必要风险标签；如果最新榜单缺失，则使用最小上下文生成提醒，不阻塞邮件。

4. **AI 输出继续严格校验并可降级。** LLM 返回必须是结构化 JSON；如果为空、非法 JSON、缺字段、含直接交易命令或比规则更激进，则拒绝并保存规则兜底解释。

## Risks / Trade-offs

- **止盈观察邮件增加打扰** → 同一持仓同类提醒按日期去重；盘中重复提醒继续走现有冷却逻辑。
- **AI 提示词修复后模型输出风格变化** → 保持 JSON schema、动作降级和禁止词过滤，失败时回到规则解释。
- **榜单上下文缺失时解释较少** → 邮件正文仍展示价格、盈亏、动态线和数据源，榜单标签缺失时明确写“未进入最新榜单上下文”。
- **乱码修复可能触及较多文案** → 只修 AI advisor、持仓提醒和相关 UI 文案，不顺手重构其它旧页面。
