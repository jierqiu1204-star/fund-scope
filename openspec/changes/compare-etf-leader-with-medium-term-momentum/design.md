## Context

动机见 [proposal.md](proposal.md)。本设计依据 2026-09-10 对 `b2311aa` 的只读核验；实施时先检查仓库是否有后续修改。

现有 V2 已有 ETF PIT 输入、候选封存、`derive_lifecycle` 和 append-only transition，但它们产出研究状态，并非完整资金账户。`etf_ranking_forward_outcomes.py` 已有 `freeze_ranking_portfolio_target` 与 `calculate_continuous_ranking_portfolio`，可以执行稀疏目标、现金／份额核算、实际交易收费、零成本伴随账户和缺价中断。之前部署诊断中共享研究 SQLite 缺失，而旧版按日期文件仍在；这需要查明配置与内容兼容性，不能直接把旧文件更名。

相关增量约束同时参考已完成的 `repair-strategy-evidence-and-ranking-comparison`，其变更尚未归档，主 specs 仍包含旧多策略描述。本变更只添加非晋升跨路线诊断，不覆盖该变更对旧引擎的退役、三候选范围、费用和留出保护。

## Goals / Non-Goals

**Goals:**

- 用同一账本回答现有 ETF 龙头突破的资金表现是否值得进一步研究，保留事件、账户与正式主指标的区别。
- 增加一个不调参的中期动量起点，保留 daily_core 低换手对照；能够定位收益差与交易频率、现金占比、集中度之间的关系。
- 用真实输入预检、一次有界运行及手算可核验样本证明实现可用；输入不足时准确指出下一步所需数据。

**Non-Goals:**

- 本次不修改信号定义、退出阈值、正式晋升规则或生产策略；不优化修复／筑底／个股分支。
- 不新增行业分类体系、订单撮合模型、整手／最小佣金模拟或交易框架。沿用现有可分份额、复权收盘、比例费用的研究模型，并明确这不是实盘成交证明。
- 不同时增加“统一换手约束”的多组实验。先比较三条完整路线，结果不能单独归因于某个因子；信号消融在本轮出现稳定差异后另提。

## Decisions

### 1. 固定三个账户，使用各自原有决策频率

| 账户 | 信号与选择 | 目标生成频率 | 资金规则 |
|---|---|---|---|
| ETF 突破 V2 生命周期诊断 | 原 V2 breakout 公式、实际可见的确认和退出事实 | 持仓名单发生变化的决策日 | 最多十槽，每槽目标 10%；事件日整组再平衡，平时份额漂移 |
| 126 日正动量月度对照 | `close[T]/close[T-126]-1>0`，收益降序、代码升序，最多十只 | 声明起始日一次，此后交易所日历月末；同日去重 | 每只目标 10%，不足留现金；月内不重发目标 |
| daily_core 低换手 | 原 `daily_reconstructable_v1` 及 Top10／排名15缓冲／至少持3日／每天最多替换1只 | 既有每日候选规则 | 保留现有每日等权目标与实际再平衡收费 |

126 个交易日是本次预注册的近半年窗口，不称作“六个自然月”，也不声称是最优周期或 MSCI 复刻。只使用一个固定值，不把原 20 日选择器改成可任意搜索的通用参数接口。现有 PIT 输入最多支持 180 根，足够这次 127 根窗口；不能沿用临时诊断中的 90 根上限。

初始日由预检的可评估性与请求范围确定并在读收益前封存，各账户同时从现金启动；动量初始日即使不是月末也仅发一次目标。月末由真实交易所日历确定，不能把当前数据的最后一天当成月末。区间最后一个决策若缺下一交易日，只记录未执行／待到期，不能同日成交。

采用当前具备事实资格的共同 ETF 研究池，不新建“行业 ETF”筛选体系；报告揭示资产类别覆盖。若含黄金、跨境或宽基 ETF，名称保持“ETF 动量”，不声称本轮已经单独验证行业动量论文。选择代表 ETF 在组合层复用现有去克隆规则，保留时点可见的映射与选代表依据；不得先删掉 V2 的同类计算输入导致其公式事实上改变。

共同可选池先按时点资格及去克隆策略确定分母，再检查127根完整历史，输出合格分子；至少十只合格后才允许各路线做信号筛选。低于十只（包括全部缺历史）是本次比较的数据不足，不产生合法空仓目标。通过该门槛后，正收益／确认信号少于十只才可按各路线规则留现金。这个最小池规模只是诊断运行条件，不替代既有更严格的资格与晋升覆盖门槛；V2额外状态缺失阻断自身，不用于缩小其他路线的选品池。

替代方案：多个回看周期、波动率加权、趋势开关、行业新分类、统一换手矩阵均能扩展研究，但会增加试验数且难定位增益，本轮不采用。

### 2. V2 只补状态到目标的窄桥接

从按日期封存的 manifest／observation／transition 读取，不使用只返回最新结果的页面作为历史源。复用 `read_etf_v2_asset_inputs`、`screen_dual_universe`、`derive_lifecycle` 及现有存储函数；不从包含 V1 proxy 和参数网格的 `run_etf_leader_historical_backtest.py` 生成 V2 账户。

- post-close `next_eligible_date` 仅是最早可继续观察日；需要实际因果确认，不能直接买入。确认日 C 的 target 使用 `signal_date=C`，已有账本在下一交易日执行。退出日 X 同理；`simulated_execution_date` 已是下一日，不能再作为 signal_date 推迟一次。
- 不用最后一个状态反向筛选旧信号。按截止时间可见的状态序列前进，晚到的 confirmation／exit 不能回填过去；中间缺必要状态观察时标记覆盖不足，不能把跳过的日期当作持续持有依据。
- 当日先退出，后从当日新确认中选入；持仓不因新资产排名更高被强制挤出。候选按现有冻结顺序 `score DESC, signal_date DESC, formula_id ASC, asset_code ASC` 选择，资产和 clone group 去重；被容量挡住的信号不进入延迟购买队列，同日退出优先。
- 仅在名单变化时生成整组十百分比槽位目标。**事件日老仓也可能为恢复目标权重发生交易并收费**，不承诺老仓份额不变；名单不变日完全不发 target。这样可直接复用账本，而不用新增事件订单引擎。
- 全仓买入时沿用账本的先卖后买和可用现金等比例缩买，手续费由账户承担，不透支。按排名确定的是入选资产，不是按排名优先花光资金。

账户目标哈希引用实际源 manifest／transition、clone selection 与新的 allocation-policy hash。V2 原公式、来源登记和原状态契约不修改；未来若要调整这些规则，必须另起研究身份。

### 3. 共用账本，不强行统一换仓日期

三条路线都调用现有连续账本。动量与 V2 提交稀疏 `targets`，`required_signal_dates` 只包含其实际必须产生目标的日期；daily_core 沿用每天的必需决策日。V2 每日输入／状态完整性在桥接前独立检查，不能因为当天未生成订单就跳过数据检查。

执行统一为决定后的下一个真实交易日合格复权收盘，不把“下一个有价格的日期”当下一交易日。基础每边 5bp 费用＋5bp 滑点，压力每边 5bp＋10bp；使用已有零成本伴随账户算毛收益。卖买收费、权重漂移、现金缩买、持仓缺价即停止的逻辑不复制。

比较共用声明初始资金、日历、来源模式、数据版本和可用资产资格；不同策略的筛选失败不应从其他策略池中扣除。共同支持集不等于三者最终买入资产交集。

替代方案：统一所有策略按月或按日交易会改变原策略；另建账户引擎又会引入第二套成本和缺价语义，两者均不采用。

### 4. 先查数据与研究目录，再考虑恢复动作

预检复用 `load_point_in_time_ranking_inputs`、ETF membership facts、V2 输入／materialization 与 `ReplayArtifactStore`。记录 requested/available 日期、原始 availability、历史根数、manifest 完成状态、clone 覆盖及实际 store 路径。

共享 store 缺失时，先核验现有配置、持久化目录和挂载；再通过既有建库／schema 路径准备研究文件。只有匹配原 schema、source/cutoff/hash 的记录可经现有研究接口重用或重放。未证实兼容的旧按日期文件保留原处，不拷贝后改名冒充新库，不写通用迁移工具。恢复单次沿用不超过55秒、单 worker、checkpoint，少量页验证成功后才给出有界续跑说明。

若当时根本没有权威名单／合格行情，修配置不能创造历史。严格 PIT 保持缺数，从真实采集时间继续积累；本轮交付读取／接线及预检能力，不为了得到曲线而扩展一个伪历史适配器。既有 current-vintage 诊断保留原身份、PIT 信用为零，不混到同池正式证据中。

替代方案：一律以当前名单回算会引入存续与时点偏差；空库自动当无信号会虚构现金优势，均拒绝。

### 5. 独立研究结果复用现有 artifact，不改原 manifest

跨路线运行使用独立 comparison run／phase，通过 `etf_action_replay/artifact_store.py` 的研究 artifact 接口封存配置、输入引用、目标序列、账本和汇总。不要直接续跑包含正式 factor/holdout 阶段的完整排名流程，也不要向不可变 V2 manifest 补写 `economic_evidence`。

优先扩展最接近的现有研究脚本入口；如没有可复用入口，只增加一个薄 CLI 编排器，不新增服务层、数据库表或 API。首轮输出 JSON 和可阅读的中文 Markdown 报告；页面和 dashboard 展示不在本轮。

报告至少列出：三条路线规则与频率、净／毛收益、最大回撤、累计交易金额／初始资金、成本拖累、交易／再平衡次数、平均仓位和现金、主题／跟踪指数集中度、数据覆盖、不可用区间、版本和原始 artifact 引用。分类不足则该项明确不可用，不按 ETF 名称猜精确行业权重。

三者只能在共同起点后的完整连续区间作账户差值比较。持仓价格中断时保存实际中断原因和已完成前缀，报告单边结果与共同比较范围；不能丢掉缺价日后连线、把不同开始日的累计收益直接排名，或仅挑各自最漂亮的阶段。月度策略的日净值点不能计作独立信号样本。

### 6. 证据门槛沿用原约束，先完成可评价能力

这是完整路线的探索性比较，不宣称只检验选品因子。配置、三路线身份、起止日期、数据模式和费用在读取收益前封存。使用开发／诊断区间，并保留后续前瞻样本的独立身份；2026年8月已读过的短样本不得改称未见验证。

本次不消费既有 ranking holdout 或 V2 锁定 A 股案例，不以代码版本或新日期边界绕过其保护。普通 ETF 预热行情不因与 A 股锁定案例同一天就被一概禁止；隔离按研究契约、标的池和受保护结果身份进行。正式 Top10 五日配对净超额、252 PIT日／40独立日期／3 folds 等门槛完全保留，不将该新动量控制加入晋升。

后续应检验多个阶段的扣费增益、风险、集中度与交易代价。首轮数据不足也可完成工程验收，报告真实缺口及何时可继续评价；不能保证实施完成就一定有统计赢家。

## Risks / Trade-offs

- [历史 PIT 名单无法补齐] → 输出精确缺口和最早可评估条件；使用小型封存 fixture 验证代码，与真实策略成绩分开。
- [事件日整组再平衡提高 V2 成本] → 将这一简化明确写入 policy hash、账本与报告，所有实际调整收费；需要保留旧仓份额的策略必须以后另起政策，不静默改变本轮。
- [126 日预热缩小共同样本，资产资格仍可能变化] → 逐日披露资格分母和排除原因，不用不完整窗口、最新名单或按收益筛选区间。
- [换手和现金差异使收益差不能归因单一信号] → 同时报告暴露、现金、费用与集中度；先回答完整路线价值，下一轮才决定是否增加受控消融。
- [复权收盘与比例费用低估真实执行限制] → 标注可分份额的研究执行假设，给固定成本压力情景，结果不称实盘收益。
- [关联既有未归档 change] → 只做 ADDED requirements，并检查三候选／旧20日／V2公式身份未变，归档时先同步前一完成变更，避免旧多策略文本覆盖新约束。

## Migration Plan

无数据库迁移。实施时先保存现有代码／公式／候选 hash 和实际研究目录配置，先跑离线回归，再做小范围只读数据预检与受限研究存储续跑，最后生成报告。只有确证配置有误时才给出最小路径／挂载修改，生产部署单独执行。

回滚只需停止新比较入口、回退相关接线／配置；保留已生成研究 artifact 作为审计记录，不删除旧 manifest 或覆盖旧结果。业务排名、持仓与通知不随研究回滚发生迁移。

研究依据： [行业动量论文](https://spinup-000d1a-wp-offload-media.s3.amazonaws.com/faculty/wp-content/uploads/sites/3/2019/09/DoIndustriesExplainMomentum.pdf)、[MSCI 动量方法](https://www.msci.com/indexes/documents/methodology/2_MSCI_Momentum_Indexes_Methodology_20250417.pdf)、[Qlib 的信号与换仓分离](https://qlib.readthedocs.io/en/latest/component/strategy.html)。本计划的126日、Top10与事件账户都是待检验的工程起点，不是上述资料验证过的最佳组合。
