## Context

FundScope 现在的 ETF 工作台已经具备短线排序、今日买点、资金配置参考、追踪持仓、邮件提醒、日线回测和盘中提醒执行回测。问题是这些能力还没有形成足够强的“策略体检”闭环：当 2026 年 6 月后回测明显走弱时，系统只能展示曲线，而不能清楚回答“是哪些标签失效、哪些行业拖累、哪些市场状态不适合继续用当前策略”。

同时，当前 ETF 资金配置参考是规则化权重：按标签、买点、得分、波动、回撤、流动性和上限约束分配。它透明但偏经验，需要引入数学优化组合做对照，参考成熟投顾/量化框架中“信号层”和“仓位层”分离的做法。

项目边界保持模块化单体。依赖方向必须遵守 `AGENTS.md` 和 `docs/backend-domain-boundaries.md`：行情数据 -> 研究信号 -> 组合配置 -> 持仓追踪 -> 风控提醒 -> 通知发送。策略体检和数学优化属于研究/组合/证据层，不得反向修改追踪持仓或邮件阈值。

## Goals / Non-Goals

**Goals:**
- 建立 ETF 策略体检能力，能解释策略近期是否失效、失效在哪些标签/行业/市场状态。
- 建立数学优化组合对照，至少支持最小波动、风险平价/HRP 风格近似、等权对照。
- 让规则组合、优化组合、等权组合共享同一 ETF 研究证据契约，避免页面、回测、验证变成多套口径。
- 在 `/short-term` 中展示体检结论、最新样本表现、优化组合差异和数据限制。
- 数据不足或近期失效时明确降级，不输出“策略可靠”或“推荐买入”措辞。

**Non-Goals:**
- 不连接券商，不自动下单，不自动卖出。
- 不让 AI 决定权重、标签或交易动作；AI 只解释已计算出的规则/优化结果。
- 不默认替换现有规则组合；优化组合第一版是对照和证据，不是自动接管。
- 不做股票、期货、期权、可转债策略。
- 不引入 Redis、任务队列或微服务拆分。

## Decisions

### 1. 策略体检使用“分层证据”，不只看总收益曲线

策略体检将结果拆成：
- 时间分段：全样本、最近 30/60/120 个交易日、用户指定的近期窗口。
- 标签维度：短线观察、高位观察、健康回踩、趋势延续、冲高别追、跌破等待等。
- 主题维度：半导体、人工智能、医药、金融、宽基、债券、黄金等。
- 执行模型：日线收盘模拟、盘中提醒执行模拟。
- 市场状态：risk_on、neutral、defensive、cash_wait。

理由：成熟框架通常不会只凭一条净值曲线判断策略有效性。用户关心的是“现在还能不能用”，因此近期样本、标签表现和行业拆解比总收益更重要。

### 2. 数学优化先做稳健对照，不做最大夏普默认

第一版优化方法：
- 等权组合：基线。
- 最小波动组合：降低组合波动。
- 风险平价/HRP 风格近似：降低单一 ETF 或单一主题对组合风险的主导。
- 规则组合：现有透明规则。

不默认做最大夏普。原因是 ETF 短线预期收益很难稳定估计，最大夏普对预期收益输入非常敏感，容易过拟合。最小波动和风险平价更适合做稳健对照。

第一版优先使用项目现有 Python 数值能力实现轻量优化，不强依赖 PyPortfolioOpt/CVXPy。若后续验证确有必要，再单独引入外部优化库。

### 3. 优化输入必须严格可信

优化只使用 verified / alternate_provider 的日线收益和可用 ETF 元数据。以下数据不得参与优化：
- 旧行情、估算价、缺失补零。
- 盘中非新鲜行情。
- 样本不足的 ETF。
- 流动性不足或数据滞后的 ETF。

如果有效 ETF 数量不足、收益矩阵缺口过多、协方差矩阵不稳定，系统 SHALL 返回“不可优化/等待数据”，而不是输出伪精确权重。

### 4. 优化结果不得直接影响持仓和邮件

优化组合只影响“ETF 资金配置参考”和回测对照。它不得：
- 自动创建或修改追踪持仓。
- 自动触发邮件。
- 修改硬止损、移动止盈、趋势转弱等风控阈值。

后续如果要让优化组合成为默认组合，必须由策略体检证明其优于规则组合，并由人工确认。

### 5. API 采用扩展字段，不破坏旧页面

现有 `/api/short-research/observation-portfolio`、ETF 回测和标签验证 API 保持兼容，新增字段承载体检和优化结果。旧字段继续可用；没有新结果时前端显示“等待体检/等待优化”，不影响现有短线研究。

## Risks / Trade-offs

- [Risk] 数学优化看起来更专业，但可能因为样本短或预期收益不稳定而误导。  
  → Mitigation: 第一版只做稳健优化对照，明确展示样本窗口、有效 ETF 数量、协方差稳定性和限制说明。

- [Risk] 近期样本太短，策略体检容易过度反应。  
  → Mitigation: 同时展示全样本、近期样本、样本外/滚动窗口，结论使用“待验证/近期失效/可观察”，不输出确定买卖建议。

- [Risk] 体检和优化可能与页面实时标签不同步。  
  → Mitigation: 所有结果必须带 evidence contract hash、signal run id、data window 和生成时间。旧口径只能显示为“旧口径结果”。

- [Risk] 计算量增加影响页面速度。  
  → Mitigation: 体检和优化作为后台任务生成快照；页面默认读取最近快照，手动按钮再触发重算。

- [Risk] 组合优化跨层调用追踪或通知。  
  → Mitigation: 优化服务只读取行情/研究信号，不读取用户追踪持仓，不调用 notifier；跨领域编排放在 jobs/workflows。

## Migration Plan

1. 新增体检结果表和优化组合快照表，旧数据不迁移。
2. 新增后台任务和手动任务入口生成体检/优化快照。
3. 前端先展示“等待体检/等待优化”，有快照后展示结果。
4. 回测加入规则组合、优化组合、等权组合对比，但保留旧回测入口。
5. 部署后手动运行一次 ETF 信号、策略体检、优化组合和回测任务，确认页面只展示同源证据。

Rollback：保留旧规则组合和旧回测 API；如果体检/优化任务失败，页面降级显示旧规则组合，不影响追踪和邮件提醒。
