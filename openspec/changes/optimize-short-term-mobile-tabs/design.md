## Context

`/short-term` 当前已经有完整的桌面工作台：顶部任务区、左侧排行榜、右侧资产详情、持仓观察、观察组合和数据问题。桌面端体验可用，但手机端所有内容纵向堆叠，导致用户必须长距离滚动才能找到详情、追踪和分析说明。

本次只优化移动端信息架构。已有 API、React Query 请求、排序结果、追踪提醒和桌面双栏布局保持不变。

## Goals / Non-Goals

**Goals:**
- 手机端默认展示短线榜单，减少首屏干扰。
- 用 `榜单 / 详情 / 追踪 / 说明` 四个标签组织内容。
- 点击榜单资产后自动进入详情标签。
- 让已买入追踪和卖出/减仓提醒在手机端可直接查看。
- 保留桌面端现有布局，包括左侧高度对齐右侧分析说明的行为。

**Non-Goals:**
- 不改后端 API、数据库、排序算法或提醒算法。
- 不改全站导航，不新增独立移动端路由。
- 不接券商、不自动交易、不改变投资建议口径。
- 不重做视觉主题，只做移动端结构和密度优化。

## Decisions

- **移动端用标签页，桌面端保持双栏。**  
  方案 A 比折叠面板更适合手机，因为用户能直接跳到追踪或说明，不需要猜哪些折叠块里有目标信息。实现上用 Tailwind 响应式 class 控制 `xl` 以下的显示结构，避免影响桌面。

- **复用现有内容块，不拆后端接口。**  
  榜单、详情、追踪、说明都复用当前页面已有数据和展示逻辑，只调整容器和条件渲染。这样减少回归风险，也避免重复请求。

- **移动端资产选择后自动切到详情。**  
  点击榜单卡片后设置 `selected` 并把移动端 tab 切为 `detail`。这符合用户“先看排名，再看单只分析”的主流程。

- **移动端顶部保留轻量状态，不展示完整桌面任务区。**  
  顶部保留模式切换、最新日期、关键计数和任务按钮入口；详细状态、观察组合和数据问题放入 `说明` 标签，降低首屏高度。

- **编码和验收分工写入任务。**  
  实施可交给 `5.3codex-spark` 子代理完成局部前端改造；最终由主代理以 `5.5 xhigh` 标准 review、运行验证、浏览器截图检查后完成。

## Risks / Trade-offs

- **移动端和桌面端渲染分支增加** → 限制改动在 `/short-term` 内，并复用同一数据变量和内容函数。
- **内容块重复导致维护成本上升** → 优先抽小型本地 render helper，而不是复制大段 JSX。
- **标签切换可能隐藏重要风险提示** → 追踪标签显示持仓处理状态；榜单和详情保留核心风险标签；说明标签放完整解释。
- **截图验收受浏览器工具可用性影响** → 优先用浏览器自动化截图；若浏览器扩展不可用，则用本机 Chrome/Playwright executable 或服务器页面截图替代。
