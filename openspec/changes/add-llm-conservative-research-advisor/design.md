## Context

当前短线研究已经能从公开基金净值和 ETF 日线数据生成确定性排序、标签、风险标记和图表。它的优点是透明、可复现；缺点是对金融小白来说解释仍偏机械，用户需要知道“为什么值得观察”“为什么高位别追”“反方风险是什么”“持有后什么情况退出观察”。

项目已有 OpenAI 兼容的 `LLMClient`，ECNU 大模型平台也提供 OpenAI 兼容接口、结构化输出和 `ecnu-plus`/`ecnu-max` 模型。新能力应复用这一接入方式，但必须把大模型限制在解释层，避免让模型直接决定排名或生成真实交易指令。

## Goals / Non-Goals

**Goals:**

- 每天在短线信号生成后，为候选基金/ETF生成多角度、中文、小白可读的研究报告。
- 使用保守动作词：`重点观察`、`高位别追`、`谨慎`、`暂不考虑`、`退出观察`。
- 让大模型报告包含机会、风险、反方观点、适合持有周期、A/C类或ETF交易限制说明、观察触发条件。
- 大模型失败时自动降级，基础排序和图表仍然可用。
- 所有模型输出结构化入库，方便页面展示、测试和历史追踪。

**Non-Goals:**

- 不做自动下单，不连接支付宝账户，不连接券商。
- 不输出目标价、保证收益、止盈止损价位或确定性收益预测。
- 不让大模型改写确定性分数、排名、标签或风险标记。
- 不要求每只基金/ETF每天都调用模型；优先分析 Top 候选、持有中资产和风险变化资产。

## Decisions

### 1. 规则先行，模型后置

短线研究服务先生成确定性信号，包括排名、分数、近期收益、回撤、波动、成交活跃度、数据新鲜度和风险标记。LLM 服务只接收这些结构化输入，输出结构化研究解释。

原因：金融场景需要可复现和可追责。模型文字可以帮助理解，但不能成为唯一判断来源。

替代方案：让模型直接读全量资产并给排名。该方案不可复现，容易产生幻觉，也难以测试，因此不采用。

### 2. 结构化输出而非自由文本

模型输出使用 JSON schema，字段包括：

- `action_label`: 保守动作词之一。
- `plain_summary`: 面向小白的一句话说明。
- `opportunity`: 机会点，必须引用输入指标。
- `risks`: 风险点列表，必须引用风险标记或指标。
- `opposing_view`: 反方观点。
- `watch_conditions`: 后续观察条件，例如趋势走弱、回撤扩大、数据滞后。
- `holding_note`: 如果用户已持有，如何理解当前状态。
- `data_limitations`: 数据限制说明。

原因：结构化输出更容易校验、入库、页面展示和测试，也更容易拒绝非法字段。

### 3. 保守动作词由规则和模型共同约束

基础动作词由确定性标签映射：

- `短线观察` -> `重点观察`
- `高位观察` -> `高位别追`
- `谨慎观察` -> `谨慎`
- `不适合短线` 或 `数据不足` -> `暂不考虑`
- 已在用户观察/模拟持有中，但跌出观察条件或触发严重风险 -> `退出观察`

LLM 可以解释动作词，但不能把弱标签提升成更积极的动作词。后端会校验并覆盖越权输出。

### 4. 每日任务分阶段执行

新增每日研究任务：

1. 同步短线公开数据。
2. 生成确定性短线信号。
3. 选择需要 LLM 分析的资产：Top N、用户关注资产、模拟盘持仓、昨日动作变化资产。
4. 调用 LLM 生成报告。
5. 校验 JSON、过滤禁用语言、保存成功或失败状态。

原因：减少模型调用成本，也避免配额不足导致整批任务失败。

### 5. ECNU 平台作为 OpenAI 兼容配置

不引入专门 SDK。使用现有 OpenAI SDK 兼容方式：

- `OPENAI_BASE_URL=https://chat.ecnu.edu.cn/open/api/v1`
- `OPENAI_API_KEY=<服务器环境变量>`
- `MODEL_NAME=ecnu-plus`

高质量批量复盘可切换 `ecnu-max`，但默认使用 `ecnu-plus` 控制成本和响应时间。

## Risks / Trade-offs

- [模型幻觉] -> 只允许模型引用输入指标，后端校验结构和禁用词；不合格则丢弃并降级。
- [配额不足] -> 只分析 Top N 和变化资产；失败不影响确定性榜单。
- [用户误解为买卖指令] -> 页面统一使用观察语言，保留研究提示和“非交易指令”说明。
- [模型输出不稳定] -> temperature 设为 0 或低温，使用 JSON schema 和固定提示词。
- [数据不是支付宝实时数据] -> 页面展示数据日期和来源，强调公开净值/ETF日线，不显示“实时支付宝同步”。
- [短线频繁操作成本高] -> 报告必须提示 A/C类、QDII确认延迟、ETF与场外基金交易差异。

## Migration Plan

1. 增加数据库表和模型配置，不影响现有短线排序接口。
2. 新增 LLM 研究报告 API，前端先以可选模块展示；没有报告时显示规则解释。
3. 在后台任务页增加“生成 AI 研究报告”按钮，手动验证后加入每日调度。
4. 服务器 `.env` 配置 ECNU API key 后启用；未配置时保持关闭。
5. 如上线后模型质量不稳定，可关闭 LLM 开关，系统回退到纯规则短线研究。

## Open Questions

- 每天默认分析多少只资产：建议 Top 20 + 持有/关注资产。
- 是否需要接入新闻源：第一版建议不接实时新闻，避免把未经校验的信息混入短线建议。
- 用户真实持仓是否参与“退出观察”：第一版可先读取本项目手动录入/导入的持仓，不连接支付宝。
