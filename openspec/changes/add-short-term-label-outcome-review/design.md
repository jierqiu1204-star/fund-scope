## Context

FundScope 已经有短线标签、买点状态、ETF 实时榜单和日线信号缓存。现有 `etf-signal-validation` spec 已要求验证 ETF 标签的未来 1/3/5/10 日表现，但用户现在提出的是更具体的产品化需求：用户看到某天的 `短线观察` 后，应能知道这个标签在最近真实历史里后续表现怎样，而不是只看到当前规则解释。

成熟量化/交易系统通常不会只看单次信号，而会做 signal validation / walk-forward validation / out-of-sample review。FundScope 第一版不训练模型，也不自动调参，因此更适合做“标签验收台账”：固定记录当时信号，未来数据出现后补结果，用统计表现约束标签可信度。

## Goals / Non-Goals

**Goals:**
- 对历史短线标签进行事后验收，回答“前几天标注短线观察后，后面几天表现怎样”。
- 在 ETF 详情页展示标签组合的历史表现：样本数、1/3/5/10 日收益、最大回撤、胜率、中位数、近期是否恶化。
- 明确样本不足时不能把标签说成可靠。
- 确保验证只使用真实未来日线数据，避免 lookahead bias 和 fallback 误导。
- 将验证结果作为“可信度证据”，不自动修改实时标签，不自动触发买卖。

**Non-Goals:**
- 不训练模型，不预测未来最高点。
- 不自动改短线评分参数。
- 不生成买入指令或保证收益措辞。
- 不用盘中临时价做历史验证；盘中价可用于实时状态，但标签验收以日线完成窗口为准。
- 不覆盖场外基金第一版；优先 ETF，因为 ETF 数据更及时、更适合短线验证。

## Decisions

### 1. 用历史 signal item 作为标签快照源

优先复用 `short_research_signal_runs/items`。每次短线排序生成时，系统已保存当时标签、分数、metrics_json、rationale_json。标签验收不重新计算历史标签，避免未来规则变化污染过去快照。

替代方案：按当前规则回放历史。放弃原因：容易引入规则版本变化和 lookahead bias，且实现更重。

### 2. 验证结果按“标签组合 + 单只资产”两层输出

- 标签组合层：`买入观察状态 + 今日买点状态 + asset_type + theme_group` 的聚合表现。
- 单只资产层：某只 ETF 最近若干次被标注后的后续表现。

这样既能回答“短线观察整体靠不靠谱”，也能回答“这只 ETF 的短线观察历史表现怎样”。

### 3. 窗口固定为 1/3/5/10 个交易日

这和当前短线场景一致：1-2 周内卖出或最多两三个月观察。第一版先不做 20/60 日未来表现，避免把短线标签解释成长线收益。

### 4. 只使用完成窗口的真实日线数据

例如 5 日结果必须等 5 个交易日后的收盘价存在才计算。未来价格缺失则标记 pending 或 excluded，不使用估算价、旧行情、盘中残缺行情补结果。

### 5. 可信度分级而不是“推荐买”

输出：
- `样本充足`：样本数达到阈值，且近期表现未明显恶化。
- `样本有限`：有样本但不足以强验证。
- `近期走弱`：最近窗口表现明显低于长期样本。
- `样本不足`：不展示可靠结论。

UI 不使用“可以买”“胜率保证”“稳赚”等措辞。

### 6. 不自动改变实时标签

验证结果只展示证据。若未来要用验证结果降级标签，必须另开变更并人工确认。

## Risks / Trade-offs

- [Risk] 用户把历史胜率理解成未来保证。→ Mitigation: UI 明确“历史样本，不代表未来”，并显示最大回撤和最差样本。
- [Risk] 样本少时指标波动大。→ Mitigation: 样本不足直接标记，不展示强结论。
- [Risk] 规则版本变化导致历史标签不可比。→ Mitigation: 保存 rule_version / parameter_version，并按版本分组或提示版本差异。
- [Risk] 每日全量补结果可能慢。→ Mitigation: 只处理未完成窗口和最近需要补齐的 signal items，使用索引和批处理。
- [Risk] 当前已有信号历史不够长。→ Mitigation: 首屏允许显示“正在积累样本”，不伪造历史。

## Migration Plan

1. 新增或扩展标签验证结果表，支持唯一键防重复。
2. 写一个幂等 job：读取历史 ETF signal items，补齐完成窗口结果。
3. 收盘后 ETF 日线更新和信号生成后运行该 job。
4. API 返回 selected asset 的验证摘要和标签组合摘要。
5. 前端在卡片和详情页展示可信度证据。
6. 部署后先用历史 signal items 回填一次验证结果。

## Open Questions

- 第一版最小样本数设多少？建议：少于 20 为样本不足，20-49 为样本有限，50+ 才显示相对可信。
- 是否把 `高位观察 + 健康回踩` 这种组合单独统计？建议保留组合维度，但 UI 默认展示当前资产对应组合。
- 是否给场外基金也做？建议第二阶段再做，因为场外基金净值延迟，短线验证口径不同。
