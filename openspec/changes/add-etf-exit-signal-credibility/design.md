## Context

FundScope 目前已经有 ETF 短线排序、资金配置参考、标签验证、盘中提醒执行回测和 Freqtrade 式参数调参。  
这些能力能回答“当前规则怎么触发”和“参数组合整体表现如何”，但还不能直接回答用户关心的后验问题：某个退出信号触发后，后面到底是继续跌、很快涨回去，还是卖飞。

成熟量化工具一般会把交易记录和退出原因拆开统计：Freqtrade 有 exit reason / enter tag / mixed tag 统计，Backtrader 有 TradeAnalyzer，vectorbt 有结构化 trades 记录。FundScope 应补一层类似的研究证据，但必须保持金融边界：只做复盘证据，不改实时邮件规则。

## Goals / Non-Goals

**Goals:**
- 为 `hard_stop`、`trailing_take_profit`、`trend_weakening`、`take_profit_watch`、`exit_watch` 建立事后可信度统计。
- 对每个理论触发事件计算触发后 1 / 3 / 5 / 10 / 20 个交易日表现。
- 分信号、分 ETF、分主题/板块输出成功避险、错杀、卖飞、样本不足等结论。
- 将可信度结果纳入 ETF 研究证据契约，能说明是否和当前信号/组合/执行模型同源。
- 在页面中展示“这类提醒历史上是否靠谱”，而不是把规则本身包装成可靠结论。

**Non-Goals:**
- 不自动修改实时邮件阈值。
- 不发送真实邮件。
- 不修改用户追踪持仓、买入价、份额或状态。
- 不连接券商，不自动交易。
- 不用 AI 决定触发点或可信度；AI 只能解释已计算出的证据。
- 不把日线 fallback 冒充盘中提醒证据。

## Decisions

### 1. 独立研究证据模块，而不是塞进实时提醒

退出信号可信度属于研究证据，不属于实时风控提醒。实现时应放在 ETF 研究证据或短线研究证据侧，避免 `risk_alerts`、`tracked_positions`、`notifier` 之间产生反向依赖。

备选方案：直接在 `tracked_positions` 里统计历史提醒。  
不采用，因为那会把用户当前持仓、真实提醒记录和研究复盘耦合在一起，也容易误写真实提醒表。

### 2. 使用“理论退出事件”而不是真实邮件日志作为主样本

真实邮件日志样本少、受用户持仓影响，不足以评估规则质量。系统应基于历史行情和当前规则契约生成理论退出事件，再统计后续表现。真实邮件日志可作为对照，但不作为唯一数据源。

备选方案：只统计真实邮件。  
不采用，因为样本太少，无法判断信号可靠性。

### 3. 盘中提醒证据优先使用盘中历史，缺失则标记证据不足

`intraday_alert` 执行模型只能用 `etf_intraday_quotes` 中的新鲜盘中历史复盘。没有盘中历史时，不能回退到日线收盘价冒充盘中触发，只能标记“盘中证据不足”。

日线可以作为单独 `daily_close` 参考，但不能证明盘中邮件策略。

### 4. 可信度分类采用保守规则

每个退出事件先计算后续表现，再分类：
- `success_avoid_loss`：触发后出现明显下跌或不再创新高，说明提醒帮助避险。
- `sold_too_early`：触发后继续上涨超过阈值，说明可能卖飞。
- `false_stop`：硬止损或趋势转弱后快速修复并上涨，说明可能错杀。
- `neutral`：后续变化不明显。
- `insufficient_future_window`：未来窗口不足，不能下结论。

分类阈值应使用动态阈值上下文或波动率分桶，而不是全市场固定同一条线。

### 5. 统计要同时给结论和限制

页面不能只显示“成功率 70%”。必须同时展示样本数、数据区间、执行模型、样本外窗口、是否同源、样本不足原因。样本不足时结论只能是“待验证/样本不足”，不能显示成“可靠”。

## Risks / Trade-offs

- 盘中历史样本少 → 页面明确显示覆盖率和样本不足，不用日线硬凑。
- 理论退出事件和真实用户操作不同 → 标注为研究复盘，不代表真实交易收益。
- 规则复盘可能引入未来函数 → 每个事件只允许使用触发时点之前可见的数据，未来数据只用于事后评价。
- 事件数量可能较多 → 只持久化事件摘要和聚合指标，不保存无用大明细。
- 与已有 healthcheck/hyperopt 重复 → 本模块只回答“退出后发生了什么”，不替代参数调参和组合回测。

## Migration Plan

1. 新增研究证据表和模型，部署 migration。
2. 新增只读评估服务和 API。
3. 新增 admin job / scheduler job，默认夜间运行。
4. 前端策略证据页增加模块。
5. 部署后先手动跑一次评估，确认样本数、覆盖率和结论。

回滚时保留表不影响现有链路；若接口关闭，实时排序、持仓追踪和邮件提醒不受影响。
