## Why

2026-09-05 的代码与线上研究汇总复核表明：当前 ETF 研究榜已使用 `daily_reconstructable_v1`，但旧验证来源仍错位，前瞻历史样本没有持续成熟，现有 PIT 流程的收益与验证阶段仍含占位实现。旧试验提示简单动量和降低换手值得优先重验，但零成本龙头回测、旧版综合榜和短样本不能证明当前策略优胜；应先让已有研究流程产出可信、可比较的结果，再决定策略投入。

## What Changes

- **先恢复证据生成**：验证按兼容的历史已发布快照处理到期样本，不依赖今日是否出榜；补齐来源版本、契约、执行与截止时间，保留精确不可用原因。
- **补通现有 PIT 流程**：用真实后续交易日、合格复权价格和已有计算器替换空输入与固定 `pending`；复用现有单 worker、checkpoint、artifact store 和证据表，支持历史样本有界续跑。
- **只比较已冻结的三组研究榜候选**：前十、换仓缓冲前十、缓冲加市场/流动性过滤。保留现有 Top10/5 日配对主指标、成本与样本门槛；另放一条冻结的 20 日纯动量 Top10 诊断基线，不增加第四候选、不替换正式基线。
- **报告真实收益与成本**：区分重叠事件收益与连续资金曲线，计算实际持仓变化、换手和费用；正式 Top10 五日配对净超额从连续账户的同窗净值提取，冻结新的研究执行/endpoint 子契约，旧固定往返收费样本保持独立。在同日期、同候选池、同执行与成本下比较，不恢复已删除的旧七策略引擎。
- **修正龙头历史研究口径**：为现有 V1 生命周期试验冻结新研究契约，采用真实入场价、入场前可见 ATR、非零费用和滑点；保留旧结果为旧口径，不据此改变实时风控、持仓或邮件。
- **完成最小验收闭环**：复用现有滚动验证和留出控制，修复孤儿测试与实际流程集成测试；通过现有 API/页面展示成熟数、有效日期、成本、版本和不足原因。

## Capabilities

### New Capabilities

无。复用现有研究、验证、存储和展示能力。

### Modified Capabilities

- `etf-signal-validation`：历史到期样本独立于今日榜单持续成熟；生产发布与研究回放按各自真实契约读取、汇总并标明来源。
- `etf-point-in-time-research-loop`：已有阶段必须实际处理后续价格、配对结果和证据；兼容历史样本可有界续跑，执行完成与样本不足分开。
- `etf-strategy-comparison-backtests`：以当前三候选取代旧多策略引擎承诺；添加不参与晋升的纯动量对照，明确可执行成本与资金曲线统计。
- `etf-leader-tactics-shadow`：新增与固定持有期试验分离的生命周期研究契约，固定入场成本、风险初始化时点与非零成本，旧结果不得冒充当前口径。

## Impact

- 后端主要落点：`short_research/service.py`、验证来源/会话规划器、`workflows/etf_point_in_time_capture.py`，以及现有 `strategy_lab` 的研究循环、候选、收益、统计验证、证据和龙头历史回测模块。
- 存储复用现有 signal/outcome/validation、experiment evidence/checkpoint 和 replay artifacts；**不新增数据库表或迁移，不新增 API 路由，不改现有字段类型，不添加依赖，不拆服务**。新增研究元数据只写已有 JSON/契约字段。
- 展示复用现有证据面板和接口；只修复当前/旧口径识别、状态和指标，不创建新驾驶舱。
- 生产排名公式、候选注册表、组合权重、追踪持仓、风控阈值和邮件行为保持冻结；所有产出均为研究证据。实时风险定义若需改变，另提版本化变更，本次不自动迁移持仓。
- 按 P0 验证恢复 → P1 三候选证据与对照 → P2 龙头历史研究 → 验收交付顺序实施。数据未达 252 个 PIT 日、40 个独立主日期和 3 个滚动区间时仍交付可用的采集/诊断能力，结论保持样本不足。
- 暂缓：V2 新形态/尾盘/低位补涨扩展、参数网格、优化器重建、旧基金实验室重写、全市场历史 PIT 补造、自动晋升与生产部署操作。本提案不承诺收益提升。
