## Context

生产诊断及原始数据见前一变更的 `data-gap-diagnosis.md`。已有事实表、可信价格修订、研究 checkpoint、调度和任务记录均可复用。当前工作区还包含已验收但未提交的比较工具，需保留。

## Goals / Non-Goals

目标是接通已存在能力并消除真实阻断。保持原策略、价格资格、PIT 截止和研究/生产依赖方向；不创建新数据平台、监控平台或通知渠道，不为了出曲线缩小分母或降低门槛。

## Decisions

1. Stage-A 在调用边界显式传入既有 61 根常量；V2 的 120 根和比较的 127 根继续独立校验。不给底层新增掩盖漏参的默认值。
2. 正式跟踪标的使用经文档及真实响应核验的明确字段，复用事实写入器追加记录。未知标的与供应商失败分开记录，真实接收时间不得倒填；基金名称推断不能作为替代。
3. 先检查价格修订选择是否混合来源/版本。若已有同一可信口径的完整时点序列，修复读取选择；否则按原采集入口补数据。不得把已知新修订替换成旧价、拼接不同价格口径或放宽可信版本注册表。所有选择有稳定顺序及来源 hash。
4. 修复受影响工作流的业务状态传递，保留正常分页中的 partial，避免全局修改所有任务语义。复用任务记录报告覆盖和阻断，先检验按时完成及无进展条件，不额外发邮件或新建系统。
5. 每次采集/研究续跑不超过 55 秒、单 worker、游标续跑。真实验收先小批、检查健康与事实变化，再有界推进；不启动失控全量回填。
6. 根因复查确认日常补采只选 61 或 300/500 根，新增薄的 180 根输入补采分支，复用原工作流、已观测交易日历、发布优先门槛、全局历史租约与可信供应商。与原深层任务每四分钟交替运行，总触发频次不增加；180 根输入就绪不等于原 300/500 根研究就绪。
7. 标的事实使用跨日续跑的整轮游标，完成一轮后才在后续交易日重扫。避免每页最多六只、每日最多 240 轮却在每天重置时永久遗漏池尾。
8. 复用已安装 AKShare 的 ETF 历史接口，保留已验证的 Tickflow 主源和现有入库契约。Eastmoney 经 AKShare 获取仍标记为同一供应商；raw OHLCV 与后复权收盘按日期校验，不以替换接口掩盖缺失。同步供应商调用必须能在超时/取消时结束，不遗留后台请求；真实响应验证通过才切换。
9. 覆盖统计使用与研究读取相同的截止前最新修订、可信版本和单源有效日期规则；不再把投影表的跨源日期并集当完整历史。复用共享只读规则，保留日线、61/180/300/500 窗口与原有分母、门槛。
10. 首次全池补采复用当前 180 根入口、租约和游标，每次仍最多 55 秒。CLI 支持整池有界续跑，并如实区分本轮结束、仍有缺口与全部合格；不引入新队列/数据库。正式研究的晋升与时点证据门槛不变。

## Risks / Trade-offs

- 外部供应商可能不提供完整历史映射 → 当次真实采集可支持今后决策，旧截止仍缺数；不伪造旧日可见性。
- 可选历史来源并不一定有完整合格窗口 → 保留明确缺口，核对采集能力而非保证立即达到覆盖。
- 旧研究阶段有正式晋升/holdout 边界 → 验收只推进需要的输入及研究阶段，不触发正式晋升或受保护样本消费。

## Migration Plan

无迁移。主代理先完成独立测试、领域边界与 Ruff，再使用既有 GitHub 部署流程。部署保留业务数据和研究 artifact；核验生效代码、任务与小批真实数据。回滚代码时保留真实追加事实，不恢复旧数据库覆盖新记录。
